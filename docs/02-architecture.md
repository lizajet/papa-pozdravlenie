# Техническая архитектура

## Архитектурное решение

Проект строится как статическое клиентское приложение на React и TypeScript. Next.js используется для структуры приложения, сборки и статического экспорта. Серверная часть для первой версии не требуется.

Главное отличие от референсной реализации — разделение движка и контента:

- движок знает, как загружать и показывать сцены;
- конфигурация знает, какие сцены существуют и в каком порядке идут;
- компоненты сцены отвечают за конкретные визуальные шаблоны;
- ассеты не содержат логики и могут заменяться независимо.

## Предлагаемый стек

- Node.js 22 LTS;
- Next.js с App Router;
- React;
- TypeScript в строгом режиме;
- CSS Modules или глобальный слой токенов плюс модули сцен;
- ESLint и Prettier;
- Vitest для логики переходов;
- Playwright для сквозного прохождения истории;
- GitHub Actions для проверки и публикации;
- GitHub Pages для первой статической версии.

Точные версии фиксируются при создании приложения.

## Состояние приложения

Для первой версии достаточно локального `useReducer`. Внешняя библиотека управления состоянием не нужна.

```ts
type ExperienceState = {
  status: "preflight" | "loading" | "playing" | "finished";
  currentSceneId: SceneId;
  visitedSceneIds: SceneId[];
  unlockedAchievementIds: AchievementId[];
  selectedAchievementId: AchievementId | null;
  audioEnabled: boolean;
  reducedMotion: boolean;
};
```

Основные события:

```ts
type ExperienceEvent =
  | { type: "START" }
  | { type: "SCENE_READY"; sceneId: SceneId }
  | { type: "CONTINUE" }
  | { type: "ANIMATION_FINISHED"; cue: string }
  | { type: "UNLOCK_ACHIEVEMENT"; achievementId: AchievementId }
  | { type: "OPEN_ACHIEVEMENT"; achievementId: AchievementId }
  | { type: "CLOSE_ACHIEVEMENT" }
  | { type: "RESTART" };
```

Переходы валидируются централизованно. Компонент сцены не должен самостоятельно знать весь маршрут истории.

## Граф сцен

Форма маршрута пока не выбрана. Модель одинаково поддерживает линейную последовательность, ветвление и смешанный граф. Это позволяет принять сценарное решение позже без смены архитектуры.

```ts
type StoryScene = {
  id: SceneId;
  type: SceneType;
  next?: SceneId | SceneBranch[];
  assets: AssetRef[];
  content: SceneContent;
  transition?: TransitionConfig;
  completion?: CompletionRule;
};
```

Возможные правила завершения сцены:

- `user-action` — пользователь нажимает кнопку;
- `animation-end` — завершилась именованная анимация;
- `timer` — прошёл заданный безопасный интервал;
- `media-end` — закончилось видео или аудио;
- `manual-cue` — шаблон сцены отправил явное событие.

Таймер не должен быть единственным способом завершить важную сцену: если событие анимации потерялось, интерфейс обязан предоставить запасной переход.

## Рендеринг

`SceneRenderer` получает описание текущей сцены и выбирает шаблон:

```text
Story config
    ↓
Experience reducer
    ↓
SceneRenderer
    ↓
Scene template + assets + content
```

Шаблоны покрывают повторяющиеся композиции. Уникальная сцена может иметь отдельный компонент, но общие кнопки, загрузчики, карточки и модальные окна не дублируются.

## Загрузка ассетов

Стратегия загрузки:

1. До старта загружается минимальный набор первой сцены и аудиопроверки.
2. При показе сцены загружаются все её обязательные ассеты.
3. После готовности текущей сцены в фоне загружается следующая.
4. При свободном соединении постепенно загружается остаток истории.

Ошибки отдельных изображений не должны блокировать сцену навсегда. После таймаута показывается резервный фон или упрощённая версия.

## Звук

Из-за ограничений браузеров музыка запускается только после пользовательского действия на стартовом экране.

Аудиосистема отвечает за:

- проверочный звук;
- петлю фоновой музыки;
- плавное появление и затухание;
- звуковые акценты сцен;
- полное отключение звука;
- продолжение истории при ошибке загрузки аудио.

Звук дополняет, но не передаёт обязательную информацию.

## Доступность

- семантические `main`, `section`, `button`, `dialog`;
- осмысленные `aria-label` для сцен и декоративных элементов;
- управление кнопками, `Enter`, `Space` и `Escape`;
- видимый фокус;
- поддержка `prefers-reduced-motion`;
- отсутствие обязательных действий на время;
- контрастный текст поверх иллюстраций;
- модальное окно удерживает фокус и возвращает его после закрытия.

## Адаптивность

Базовый художественный холст проектируется в одном целевом соотношении сторон. Для других экранов используются:

- `object-fit: cover` и управляемая точка кадрирования;
- безопасные зоны для текста и кнопок;
- масштабирование типографики через `clamp`;
- отдельные композиционные поправки для узкого экрана;
- предупреждение вместо сломанной сцены на критически маленьких размерах.

Целевые режимы нужно утвердить до производства иллюстраций. Предварительно: ноутбук/десктоп — основной, планшет — поддерживаемый, телефон — упрощённый вертикальный вариант.

## Сборка и публикация

Next.js экспортирует проект в каталог `out`. Конфигурация автоматически учитывает путь репозитория для GitHub Pages.

CI выполняет:

1. установку зависимостей через `npm ci`;
2. линтинг;
3. модульные тесты;
4. статическую сборку;
5. короткое сквозное прохождение;
6. публикацию артефакта `out`.

## Наблюдаемые риски

| Риск | Последствие | Мера |
|---|---|---|
| Тяжёлые изображения | Долгий чёрный экран | WebP/AVIF, размеры под целевой холст, поэтапная загрузка |
| Потерянный `animationend` | История зависает | Резервный таймер и доступная кнопка продолжения |
| Автовоспроизведение заблокировано | Нет музыки | Явный стартовый жест и бесшумный fallback |
| Текст не помещается | Карточка обрезается | Ограничения длины, внутренний скролл, редакционная проверка |
| Слишком много уникального CSS | Трудные правки | Шаблоны сцен и единые motion-токены |
| Публикация личных материалов | Нарушение приватности | Согласование списка ассетов перед деплоем |
