# Референс: «Тёма — дорога к своим»

## Ссылки

- Опубликованный интерактивный проект: <https://amelka-karamelka.github.io/tema-doroga-k-svoim/>
- Публичный репозиторий с исходниками: <https://github.com/Amelka-Karamelka/tema-doroga-k-svoim>
- Основная игровая логика референса: <https://github.com/Amelka-Karamelka/tema-doroga-k-svoim/blob/main/app/game.tsx>
- Стили и анимации референса: <https://github.com/Amelka-Karamelka/tema-doroga-k-svoim/blob/main/app/globals.css>

Референс просмотрен и пройден полностью 20 сентября 2026 года.

## Зачем он зафиксирован

Это основной ориентир по формату и техническому подходу. В новых рабочих сессиях его нужно использовать, чтобы быстро восстановить контекст проекта и проверить желаемый характер взаимодействия.

Референс демонстрирует персональную браузерную историю, в которой пользователь последовательно проходит рисованные сцены, запускает переходы кнопками, наблюдает автоматические перемещения героя, читает личные послания и открывает коллекционные достижения.

## Что важно изучать в референсе

- ощущение цельного путешествия вместо набора слайдов;
- чередование пользовательских действий и автоматических переходов;
- сцены из нескольких независимых визуальных слоёв;
- медленное движение камеры на статичных иллюстрациях;
- спрайтовая ходьба персонажа;
- CSS-эффекты дыма, света, искр, воды и брызг;
- предварительная загрузка текущей и следующей сцены;
- стартовый жест для разрешения воспроизведения музыки;
- карточки с длинными личными текстами;
- финальная интерактивная коллекция;
- полностью статическая сборка и публикация через GitHub Pages.

## Наблюдаемая техническая реализация

На момент просмотра референс использовал:

- Next.js, React и TypeScript;
- один основной клиентский компонент с перечнем состояний сцен;
- переключение сцен через React state;
- `onAnimationEnd`, таймеры и кнопки как сигналы перехода;
- большой глобальный CSS-файл с покадровыми и камерными анимациями;
- изображения, видео, музыку и значки из каталога `public`;
- `output: "export"` для статической сборки;
- GitHub Actions для публикации каталога `out` на GitHub Pages.

## Что переносим как принцип

- статический сайт без сервера;
- выразительные полноэкранные сцены;
- один основной интерактивный шаг на экран;
- комбинацию фоновых иллюстраций, прозрачных слоёв и CSS-анимаций;
- предварительную загрузку ассетов;
- устойчивые переходы между сценами;
- доступность управления с клавиатуры;
- автоматическую публикацию по постоянной ссылке.

## Что не копируем напрямую

- сюжет, маршрут и структуру глав;
- персонажей и персональные истории;
- тексты и названия достижений;
- иллюстрации, музыку, видео и другие авторские ассеты;
- исходный код целиком;
- конкретный художественный мир и композиции сцен.

Наша реализация создаётся заново. Референс используется для понимания формата, ритма взаимодействия и набора технических приёмов.

## Архитектурное улучшение относительно референса

В референсе большая часть сюжета и отображения находится в одном компоненте. В нашем проекте движок, конфигурация контента, шаблоны сцен и ассеты разделяются. Это позволит менять будущий сценарий без переписывания всей логики приложения.
