# План реализации

## Этап 1. Сбор материала

Результат:

- заполненный портрет героя;
- список участников;
- банк историй и цитат;
- список визуальных мотивов;
- ограничения по приватности;
- набор тем и эмоциональных ориентиров без выбора финальной формы.

Техническая работа на этом этапе ограничивается созданием структуры данных и заглушек.

## Этап 2. Концептуальные варианты

Результат:

- 2–4 разные концепции опыта;
- сравнение маршрутов и механик;
- приблизительная оценка объёма контента и ассетов;
- технические риски каждого варианта;
- рекомендация без автоматического утверждения.

Конкретный сценарий фиксируется только после отдельного обсуждения и выбора концепции.

## Этап 3. Вертикальный срез

После выбора сценария собирается один законченный фрагмент:

- переходная сцена;
- встреча;
- памятный момент;
- послание;
- 1–2 достижения;
- звук и загрузчик;
- адаптивность и reduced-motion.

Вертикальный срез проверяет художественный стиль и техническую схему до производства всего проекта.

## Этап 4. Полная реализация

- создание оставшихся ассетов;
- заполнение конфигурации истории;
- реализация уникальных сцен;
- выбранная финальная механика;
- оптимизация загрузки;
- сквозные тесты.

## Этап 5. Редактура и QA

- проверка имён и фактов;
- вычитка текстов;
- проверка всех кнопок и автоматических переходов;
- проверка звука и беззвучного режима;
- проверка Chrome, Safari и Firefox;
- проверка целевых размеров экрана;
- проверка прямого открытия GitHub Pages;
- согласование личных материалов.

## Этап 6. Публикация

- финальная статическая сборка;
- публикация через GitHub Actions;
- проверка публичной ссылки в чистом браузере;
- резервная копия релиза;
- передача ссылки и короткой инструкции организатору.

## Ближайшие решения

До начала разработки необходимо определить:

1. Кто главный герой и какой повод.
2. Дату, к которой всё должно быть готово.
3. Список участников и ответственного за сбор материалов.
4. Основное место или метафору путешествия.
5. Целевые устройства: ноутбук, большой экран, телефон.
6. Нужны ли голоса участников или только музыка.
7. Будет ли репозиторий и опубликованный сайт публичным.

## Первый технический инкремент

После утверждения исходных вводных:

1. Инициализировать приложение.
2. Добавить типы истории и пример конфигурации.
3. Реализовать reducer переходов.
4. Создать стартовый экран, загрузчик и два шаблона сцен.
5. Добавить временные изображения-заглушки.
6. Настроить статическую сборку и preview.
7. Написать тест полного маршрута на тестовой истории.
