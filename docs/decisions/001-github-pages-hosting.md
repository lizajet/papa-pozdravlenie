# Решение 001: публикация через GitHub Pages

**Статус:** принято 20 сентября 2026 года.

## Решение

Первую версию поздравления публикуем на GitHub Pages. Проект собирается как статический сайт, а GitHub Actions автоматически публикует готовую сборку после изменений в основной ветке репозитория.

Предполагаемый адрес:

```text
https://<github-user>.github.io/<repository>/
```

Конкретные имя пользователя, репозиторий и итоговый адрес будут записаны после создания репозитория.

## Что это означает для проекта

- отдельный сервер не требуется;
- база данных не требуется;
- регулярная оплата хостинга не планируется;
- сайт открывается по обычной веб-ссылке;
- изменения публикуются автоматически, а адрес остаётся прежним;
- изображения, музыка, видео и код поставляются одной статической сборкой;
- позже можно подключить собственный домен без изменения архитектуры приложения.

## Как выглядит публикация

```text
Изменения в проекте
  → отправка в GitHub
  → автоматическая проверка и сборка
  → публикация папки out
  → обновление сайта по постоянной ссылке
```

## Технические требования

- Next.js работает в режиме `output: "export"`;
- сборка создаётся командой `npm run build`;
- результат сборки находится в каталоге `out`;
- workflow GitHub Actions запускается при обновлении основной ветки;
- в настройках репозитория источником GitHub Pages выбирается GitHub Actions;
- конфигурация учитывает префикс пути репозитория для всех ассетов.

## Ограничения

- опубликованный сайт доступен любому человеку, у которого есть ссылка;
- секреты, персональные данные, которые нельзя публиковать, и приватные ключи нельзя помещать в сборку;
- серверные функции, авторизация и база данных в выбранной схеме отсутствуют;
- если позднее потребуется доступ по паролю, хостинг придётся дополнить защитой или заменить.

## Причина выбора

Для поздравления требуется автономный сайт без серверной логики. GitHub Pages даёт постоянную ссылку, автоматические обновления и не требует обслуживания отдельного сервера. Это соответствует принятой архитектуре статического приложения.
