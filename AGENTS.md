# Project instructions

## Version control

- Commit repository changes after every completed, coherent step of work.
- Keep each commit focused on the step that was just completed.
- Before committing, review `git status` and the staged diff.
- Do not include unrelated user changes in a commit.
- Do not amend, squash, rebase, or rewrite existing commits unless the user explicitly asks.
- If a step changes no tracked files, no commit is required.

## Project context

- Read `README.md` before making project changes.
- Treat documents under `docs/decisions/` as accepted decisions until the user changes them.
- The primary external reference is recorded in `docs/references/tema-doroga-k-svoim.md`.
- Do not copy the reference project's code or assets directly; reproduce only general technical principles with original implementation and materials.
- The story and its structure are intentionally not fixed yet.
